# 파일 통돌이

개발 과정에서 흩어진 설계 문서, 테스트 결과, AI 협업 문서를 폴더 목록에 맞춰 정리하고 인수인계와 지식 보관으로 연결하는 로컬 에이전트입니다.

프로그램이 먼저 로컬 규칙으로 분류합니다. 판단하기 어려운 문서만 사용자가 골라 Liner에 파일명 또는 본문 분석을 요청합니다. 목적지와 새 폴더를 검토하고 승인하면 실제 파일을 이동합니다. 정리한 자료는 목록 문서와 인수인계 초안으로 남기고 지식센터에 복사할 수 있습니다.

> **심사용 Liner API 키**: 앱을 실행한 뒤 왼쪽 메뉴 **[추가 기능] → [Liner API 키]**에서 붙여 넣고 **[저장]**하세요. 바로 적용됩니다. 키는 코드·저장소·`.env` 파일에 두지 않습니다(환경 변수 `LINER_API_KEY`도 지원).

## 실행 방법

### 1. 소스에서 실행 — `start-run`

저장소 최상위 폴더에서:

| macOS | Windows |
|---|---|
| `./start-run.sh` | `start-run.cmd` 더블클릭 |

처음 실행할 때 실행 도구 [uv](https://docs.astral.sh/uv/)가 없으면 설치할지 묻고(관리자 권한 불필요), Python과 패키지를 받은 뒤 시작합니다(1~2분). 다음부터는 바로 뜹니다.

브라우저가 `http://tongdory.localhost:8765/`로 열립니다(안 열리면 `http://127.0.0.1:8765/`). 종료는 화면 왼쪽 아래 **[앱 종료]**입니다.

### 2. 배포본 만들기 — `start-build`

Python 없이 실행되는 배포본(macOS `Tongdory.app`, Windows `Tongdory.exe`)을 ZIP으로 만듭니다. 각 OS에서 실행합니다.

| macOS | Windows |
|---|---|
| `./start-build.sh` | `start-build.cmd` 더블클릭 |

필요한 도구(uv, Python 3.12 이상, C 컴파일러)가 없으면 설치할지 묻고 이어서 빌드합니다. macOS는 Xcode Command Line Tools 설치 창이 뜨면 설치를 마친 뒤 다시 실행합니다. 결과는 `src/dist/Tongdory-<버전>-<OS>-<아키텍처>.zip`이고, 이 ZIP을 그대로 나눠 주면 됩니다. 빌드는 수 분, Windows 첫 빌드는 1시간 이상 걸릴 수 있습니다.

**배포본 실행**: ZIP을 풀고 `Tongdory.app` / `Tongdory.exe`를 더블클릭합니다. 서명하지 않은 앱이라 처음 한 번 보안 경고가 나옵니다.
- macOS: ZIP을 푼 폴더에서 `xattr -dr com.apple.quarantine Tongdory.app`
- Windows: SmartScreen 창에서 [추가 정보] → [실행]

### Liner API 키 입력

로컬 검사와 직접 정리는 키 없이 됩니다. Liner 분석에는 키가 필요합니다.

앱 화면 왼쪽 메뉴 **[추가 기능] → [Liner API 키]**에서 키를 붙여 넣고 **[저장]**을 누릅니다. 저장할 때 Liner에 키가 맞는지 확인하고(요금 없음), 다시 시작하지 않아도 바로 적용됩니다. 키를 바꿀 때도 같은 화면을 씁니다. 소스 실행과 배포본 모두 같습니다.

- 키는 이 PC의 앱 데이터 폴더(macOS `~/Library/Application Support/Tongdory2/`, Windows `%LOCALAPPDATA%\Tongdory2\`)에 본인만 읽을 수 있는 전용 파일로 저장됩니다. 저장소, 코드, `.env` 파일에는 두지 않으며, `.env`에 적은 `LINER_API_KEY`는 읽지 않습니다.
- 환경 변수 `LINER_API_KEY`가 있으면 그 값이 먼저 쓰입니다.
- 같은 요청은 캐시를 재사용하므로, 새 호출을 확인하려면 아직 분석하지 않은 문서를 고릅니다. 호출 내역은 상황판 **Liner 사용 현황 → 사용 이력 보기**에 있습니다.

### 자주 쓰는 옵션

- 포트 바꾸기: `TONGDORY_PORT=8766 ./start-run.sh` (Windows PowerShell `$env:TONGDORY_PORT="8766"; .\start-run.cmd`)
- 브라우저 자동으로 열지 않기: `./start-run.sh --no-browser` (Windows `start-run --no-browser`)
- 실행 로그: 앱 데이터 폴더의 `logs/tongdory.log`

## 가상 데이터로 체험

아래 명령은 개인 파일 대신 생성된 가상 홈과 별도 앱 데이터를 사용합니다. 출력 경로는 새 폴더로 지정하세요.

```sh
uv run --locked python scripts/make_demo_data.py --out demo/review
TONGDORY_HOME="$PWD/demo/review/home" TONGDORY_DATA_DIR="$PWD/demo/review/appdata" ./start-run.sh
```

화면에서 추천 폴더 목록 또는 가상 과제의 기존 구조를 고르고, 가상 홈 안의 바탕화면·다운로드 등을 정리 대상으로 지정합니다. 저장 폴더도 같은 가상 홈 안에서 선택합니다. 실제 파일을 옮기므로 체험에는 생성한 데이터만 사용하세요.

실제 시연과 같은 대량 데이터가 필요하면 다음 명령으로 10만 개를 생성할 수 있습니다. 기본 체험에는 위의 작은 데이터셋으로 충분합니다.

```sh
uv run --locked python scripts/make_recording_dataset.py --out demo/recording_review
TONGDORY_HOME="$PWD/demo/recording_review/home" TONGDORY_DATA_DIR="$PWD/demo/recording_review/appdata" ./start-run.sh
```

대량 데이터의 폴더 목록은 `demo/recording_review/계획한_폴더목록.txt`에 생성됩니다. 정리 대상은 가상 홈의 `Documents/기존과제_자료`, `Development/가상플랫폼_개발`, `Downloads`, 저장 폴더는 `Documents/가상플랫폼_2026`입니다. 기존 출력은 덮어쓰지 않습니다.

## 화면 순서

| 화면 | 할 일 |
|---|---|
| 계획한 폴더 목록 | 기존 폴더, 폴더 목록 문서, 추천 목록 중 하나로 구조를 정합니다. 목록은 저장해 재사용·공유할 수 있습니다. |
| 정리 대상 폴더 | 검사할 폴더를 한 곳 이상 지정합니다. 하위 폴더도 검사합니다. |
| 저장 폴더 | 정리한 파일을 모을 폴더를 지정합니다. |
| 분석·검토 | 검사할 파일 종류를 선택하고 로컬 분류 결과를 검토합니다. 필요한 문서만 Liner에 분석을 요청하거나 목적지를 직접 지정합니다. |
| 정리 실행 | 옮길 파일·새 폴더·옮기지 않을 사유를 확인하고 승인합니다. 파일 이동 기록과 되돌리기를 제공합니다. |
| 완료와 인수인계 | 실제 정리 결과를 확인하고 MD·JSON·TXT 목록, 인수인계 초안, 지식센터 보관으로 이어갑니다. |

설정 화면은 `/setup/structure` → `/setup/sources` → `/setup/destination` 순서입니다. AI 협업 문서를 원래 위치에 두고 목록화하는 별도 기능은 `/s2a`에서 사용할 수 있습니다.

### 폴더 목록 문서 예시

Word(`.docx`)와 Excel(`.xlsx`)은 `폴더 경로` 열이 있는 표를 읽습니다. Excel의 `단계`·`산출물` 표도 지원합니다. Markdown(`.md`)과 텍스트(`.txt`)는 UTF-8로 한 줄에 상대 경로 하나씩 적습니다.

```text
분석/요구사항정의서
설계/화면설계서
보고/회의록
```

## Liner API를 사용한 기능

외부 분석은 사용자가 선택하고 전송 내용을 확인한 뒤 승인해야 실행됩니다. 파일명 분석과 본문 분석의 전송 범위를 구분합니다.

| 기능 | 사용하는 API | 처리 방식 |
|---|---|---|
| 1차 파일명 분석 | Chat `/chat/completions` | 마스킹한 파일명과 계획한 폴더 목록으로 목적지와 근거를 제안합니다. 파일 본문은 보내지 않습니다. |
| 2차 본문 분석 | Decisions `/decisions` | 선택한 문서의 과제 연관성을 판정하고, 후보 폴더 중 목적지를 판정합니다. |
| 본문 분석의 후보 비교 | Embeddings `/embeddings`, Rerank `/rerank` | 마스킹한 발췌와 폴더 설명의 유사도로 후보를 좁힌 뒤 순위를 비교합니다. |
| 새 폴더 제안 | Chat `/chat/completions` | 기존 목록에 맞는 목적지가 없을 때 이름과 근거를 제안합니다. 사용자가 승인해야 생성합니다. |
| 선택적 인수인계 요약 | Chat `/chat/completions` | 별도로 승인한 파일명·제목 등으로 요약을 만듭니다. 기본 초안 작성은 로컬에서 처리합니다. |
| 공개 규격 출처 검색 | Search `/tools/search/web` | 규격 번호로 만든 검색어를 사용자가 확인·승인할 때 검색합니다. 자동 분류와 별개이며 파일 본문·경로는 보내지 않습니다. |

본문 분석의 발췌와 비교 폴더는 전송 전 상세 화면에서 확인합니다. 민감 정보 감지·마스킹은 로컬에서 수행하지만 모든 민감 정보를 탐지한다고 보장하지 않으므로 전송 내용을 직접 검토해야 합니다. 분석 후 받은 제안은 사용자가 다시 체크해야 이동 계획에 포함됩니다.

**호출 수와 이동 수는 다릅니다.** 한 문서의 본문 분석에 여러 API가 쓰일 수 있고, 분석 후 이동을 선택하지 않아도 호출 비용은 발생합니다. 사용 이력에는 외부 호출·캐시 재사용·응답 비용과 추정 비용을 구분해 기록합니다. 비용은 문서 수에 비례하는 고정 요금이 아닙니다.

구현 위치: API 통신·캐시·사용 기록은 `src/tongdory2/liner/`, 파일명·본문 분류는 `src/tongdory2/catalog/pipeline.py`, 전송 승인과 작업 진행은 `src/tongdory2/web/routes/s2.py`입니다.

## 여러 묶음으로 분석

한 번에 최대 2,000개를 최근 수정순으로 선택합니다. 작업 시작 시 폴더를 탐색해 파일 목록을 SQLite에 한 번 저장합니다. **다음 묶음 로컬 검사**에서는 목록의 미처리 항목만 꺼내 실제 경로와 파일 변경 여부를 확인합니다. 서버를 다시 시작해도 목록과 진행 상태를 이어갑니다. 파일 목록 작성, 로컬 검사, 외부 분석은 백그라운드에서 실행합니다.

폴더에 새 파일을 추가했거나 이미 검사한 파일을 수정했다면 **새 파일·변경 파일 확인**을 누릅니다. 이때 목록을 다시 탐색하고 변화 없는 검사 완료 항목은 유지합니다. 동의 화면이 열린 뒤 파일이 바뀌면 해당 묶음을 다시 검사하고 전송 동의를 받습니다.

각 묶음은 따로 검토하고 이동합니다. 다음 묶음의 분석을 승인하기 전에 현재 묶음의 이동 계획을 처리하세요. 중복·버전 비교는 각 묶음 안에서 수행합니다. 폴더 깊이 제한이나 읽기 오류가 있으면 전체 범위를 미확정으로 표시합니다.

묶음 크기를 줄이려면 `TONGDORY_BATCH_SIZE=500 ./start-run.sh`로 실행합니다. 허용 범위는 1~2,000개입니다.

## 인수인계 초안

상황판에서 **인수인계 초안 만들기**를 열어 작성합니다. 저장 위치에 분석 범위, 산출물 체크리스트, 자료 링크, 다음 담당자 확인 사항을 담은 `README_인수인계.md`를 만듭니다. Liner 요약은 전송할 폴더명·파일명·문서 제목을 미리 보고 승인한 경우에 추가합니다. 기존 분석에서 민감으로 분류한 파일은 목록에서 제외합니다. 같은 이름이 있으면 번호가 붙은 새 파일로 저장됩니다.

## 다른 브라우저에서 열기

같은 PC에서 Chrome, Safari 등으로 같은 주소를 열면 같은 서버의 설정·분석 진행률·결과·실행 기록이 나타납니다. 안내 알림은 각 브라우저에 따로 표시됩니다. 같은 분석 승인이나 초안 작성 요청을 동시에 보내도 한 번만 시작합니다. 다른 화면에서 설정이 바뀌면 오래된 설정 화면에서 저장할 때 다시 확인을 요청합니다.

별도 작업 환경이 필요하면 데이터 폴더와 포트를 함께 바꿔 실행합니다.

```sh
TONGDORY_DATA_DIR="$PWD/demo/별도작업" TONGDORY_PORT=8766 ./start-run.sh
```

## 서비스 이름과 개발 범위

화면·브라우저 제목·안내·내보내기 기본 파일명에는 **파일 통돌이**를 사용합니다. 세탁통 안에 문서를 넣은 아이콘은 파일을 분류하고 정리한다는 의미입니다. 기능 메뉴에는 실제 작업을 나타내는 표현을 사용합니다.

Python 패키지 이름은 `tongdory2`, 실행 명령은 `tongdory`, 설정 환경 변수는 `TONGDORY_*`입니다.

**이 저장소의 코드는 모두 대회 기간(2026-11-12 ~ 11-25)에 새로 작성했습니다.** 기존 결과물을 이어받은 부분은 없습니다. 개발한 기능은 폴더 목록 가져오기·저장, 로컬 분류, 선택적 Liner 분석, 승인 후 파일 이동과 되돌리기, 인수인계 문서 및 지식센터 보관입니다. 온톨로지 저장소 연계는 향후 확장 방향이며 현재 기능에 포함되지 않습니다.
